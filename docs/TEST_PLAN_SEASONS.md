# План ручного тестирования — сезоны, выходы, Quick-Kick

Функции из обновления: участники сезона (`is_active`), алерты о выходе из чата, Quick-Kick, `/season_manage`, фильтрация таблиц TOVA, архив сезонов, пересылка `pending_admin`, редактирование сообщений в ЛС.

**Описание функций:** [`NEW_FEATURES.md`](NEW_FEATURES.md)

**Сначала** пройдите этот план локально. **После** успешной проверки — обновите код на сервере, **не трогая** `data/bot.db` (см. `README.md` → «Обновление на сервере»).

---

## Участники теста

| Роль | Кто | Требования |
|------|-----|------------|
| **A** | Админ | ID в `ADMIN_IDS`, `/start` в ЛС бота |
| **A2** | Админ по юзернейму (опционально) | Только в `ADMIN_USERNAMES`, `/start` в ЛС |
| **B** | Игрок TOVA | Никнейм зарегистрирован, `/start` в ЛС |
| **C** | Тестовый участник чата | Может выйти из `MAIN_CHAT_ID` (лучше отдельный аккаунт) |

В `.env` должны быть заданы: `MAIN_CHAT_ID`, `ADMIN_IDS`, `CURRENT_SEASON`, `DATABASE_URL` (или `./data/bot.db`).

---

## Перед стартом

- [х] Бот запущен локально: `python bot.py` (или Docker с примонтированным `./data`)
- [х] В логе: `journal_mode=wal`, нет traceback при старте
- [х] Бот — **админ** чата `MAIN_CHAT_ID` (нужно видеть `chat_member` события)
- [х] A нажал `/start` в ЛС (иначе алерты не дойдут)
- [х] B зарегистрировал никнейм: TOVA → Регистрация → Изменить никнейм
- [х] У B есть хотя бы один подтверждённый матч в текущем сезоне (для проверки таблицы) — *опционально, но желательно*

После первого запуска с новым кодом SQLAlchemy создаст таблицы `seasons` и `season_participants` **поверх** существующей БД. Старые матчи и пользователи **не удаляются**.
