## 1. Сезоны TOVA в БД

Раньше номер сезона задавался только через `CURRENT_SEASON` в `.env`. Теперь сезоны хранятся в таблице `seasons`.

| Поле | Описание |
|------|----------|
| `number` | Номер сезона (32, 33, …) |
| `is_current` | Текущий активный сезон (ровно один) |
| `is_finished` | Сезон завершён админом |
| `started_at` / `finished_at` | Временные метки |

**Bootstrap при первом запуске:**

- Если таблица `seasons` пуста — создаётся сезон с номером из `CURRENT_SEASON` (по умолчанию `1`).
- Игроки с зарегистрированным никнеймом попадают в `season_participants` текущего сезона.
- Существующие пользователи и матчи **не удаляются**; `create_all` только добавляет недостающие таблицы.

**Сервис:** `services/seasons.py`

## 2. Участники сезона и фильтрация статистики

Таблица `season_participants` связывает пользователя с сезоном.

| Поле | Описание |
|------|----------|
| `user_id` | Ссылка на `users` |
| `season_id` | Ссылка на `seasons` |
| `is_active` | `True` — участвует в текущем сезоне; `False` — снят |

### Где учитывается `is_active`

Для **текущего** сезона (таблица, бомбардиры, «Статистика сезона»):

- в выборку попадают только участники с `is_active = True`;
- матчи учитываются только со статусом `confirmed`.

### Когда `is_active` становится `False`

- кнопка **Quick-Kick** под алертом о выходе из чата;
- команда `/ban` (деактивация в текущем сезоне);
- завершение сезона через `/season_manage` (деактивация всех участников).

`/unban` **не** восстанавливает `is_active` — это ожидаемое поведение.

### Личная статистика

Игрок по-прежнему может открыть **TOVA → Статистика** и увидеть свои матчи, даже если деактивирован в сезоне.

**Сервис:** `services/tova_stats.py` (параметр `historical=False` для текущего сезона).

## 3. Выход из чата и Quick-Kick

### Алерт админам

При событии `chat_member` в чате `MAIN_CHAT_ID`, если участник **сам вышел** (`LEFT`) или **кикнут** (`KICKED`):

- всем админам (`ADMIN_IDS` + `ADMIN_USERNAMES` с `/start` в ЛС) приходит сообщение с именем, @username, ID и номером текущего сезона;
- под сообщением — inline-кнопка **«❌ Снять с турнира»**.

**Не срабатывает** для: других чатов (RI, VSA), ботов, выхода самого бота.

### Quick-Kick

| Действие | Результат |
|----------|-----------|
| Админ нажимает кнопку | `is_active = False` для игрока в текущем сезоне |
| Повторный клик | «Игрок уже вычеркнут из базы сезона N» |
| Не-админ | «Недостаточно прав» |
| Пересланное сообщение | Кнопка не работает (ограничение Telegram) |

После успешного снятия текст алерта редактируется, кнопка исчезает.

**Обработчик:** `handlers/member_leave.py`

**Требования к боту в чате:** права админа, в т.ч. видеть список участников (для `chat_member`).

## 4. Управление сезонами `/season_manage`

Команда доступна **только** пользователям из `ADMIN_IDS` (не `ADMIN_USERNAMES`).

| Кнопка | Действие |
|--------|----------|
| **Завершить текущий сезон** | `is_finished = True`, все участники деактивированы, сезон уходит в архив |
| **Начать новый сезон** | Создаётся сезон N+1; нельзя, пока текущий не завершён |

После начала нового сезона:

- таблица и бомбардиры пусты, пока нет `confirmed` матчей;
- игроки снова попадают в участники при регистрации/сохранении никнейма;
- матчи прошлого сезона не попадают в статистику нового — смотреть через **Архив сезонов**.

**Обработчик:** `handlers/season_manage.py`

## 5. Архив сезонов TOVA

Путь в меню: **TOVA → Архив сезонов**.

| Экран | Содержимое |
|-------|------------|
| Список сезонов | Все завершённые сезоны (не текущий) |
| Меню сезона | Статистика / Таблица TOVA / Бомбардиры TOVA |
| Статистика | Лидеры, топ-5, общие цифры по `confirmed` матчам того сезона |
| Таблица / бомбардиры | Полная историческая сетка **без** фильтра `is_active` |

Флаг `historical=True` в `services/tova_stats.py` отключает фильтр активных участников.

**Обработчик:** `handlers/tova/stats.py`  
**Клавиатуры:** `keyboards/tova.py` (`tova_archive_list_kb`, `tova_archive_season_kb`)

## 6. Пересылка матчей `pending_admin`

Матч TOVA после подтверждения соперником переходит в статус `pending_admin` и рассылается админам TOVA на проверку.

### Автоматически при старте бота

При каждом запуске (`bot.py`) вызывается `resend_pending_admin_cards()`:

- находятся все матчи в статусе `pending_admin`;
- карточки повторно отправляются админам TOVA (`TOVA_ADMIN_ID` + `ADMINS_TOVA` с `/start`).

В логе: `TOVA pending_admin on startup: N match(es), M delivery(ies)`.

### Вручную: `/pending_tova`

Доступно админам TOVA (`is_tova_admin` — по ID или юзернейму из настроек).

Ответ:

- `Нет матчей TOVA в статусе pending_admin.` — если очередь пуста;
- иначе — сколько матчей и доставок отправлено.

**Сервис:** `services/tova_reviews.py`  
**Обработчик:** `handlers/results.py`

## 7. Редактирование сообщений в ЛС

Чтобы навигация по inline-кнопкам не засоряла личку, бот **редактирует** текущее сообщение вместо отправки нового.

### Общий модуль

`handlers/callback_ui.py`:

| Функция | Назначение |
|---------|------------|
| `edit_screen()` | Текстовые экраны: `edit_text`; если было фото — удалить и отправить текст |
| `send_photo_pages()` | Таблица/бомбардиры: удалить меню, отправить фото (кнопки на последней странице) |

Ошибка `message is not modified` игнорируется.

### Где используется

| Модуль | Поведение |
|--------|-----------|
| `handlers/menu/__init__.py` | Всё главное меню и подменю |
| `handlers/tova/stats.py` | Статистика, архив, навигация TOVA |
| `handlers/tova/registration.py` | Смена/удаление никнейма через callback |

### Что остаётся новыми сообщениями

- `/start`, `/help` и ответы на текст пользователя (FSM никнейма, сдача результата);
- подтверждение матчей TOVA (диалог с игроками и админами);
- несколько страниц таблицы подряд (промежуточные фото без кнопок).

**Ожидаемое поведение:** TOVA → Архив → Сезон → Назад — одно сообщение меняется на месте.

## 8. Обновление на сервере без потери данных

```bash
cd /opt/game_bot
git pull
docker compose up -d --build
docker compose logs -f bot
```

**Сохранить:** каталог `./data` (`bot.db`, `bot.db-wal`, `bot.db-shm`).

**Не делать** на проде, если нужны данные:

```bash
rm -f data/bot.db data/bot.db-wal data/bot.db-shm
```

При копировании БД для локального теста копируйте **все три** файла и останавливайте бот на сервере.

Подробнее: [`README.md`](../README.md) → «Обновление на сервере».
