# План разработки: Cream Nemesis Bot

Поэтапный план с разделением на модули. Каждый этап даёт рабочий инкремент: бота можно запускать и проверять до перехода дальше.

**Стек:** aiogram 3.x · SQLAlchemy async + SQLite · Pillow · python-dotenv  
**Зависимости этапов:** строго сверху вниз — следующий этап опирается на предыдущий.

---

## Ключевые технические требования

Три пункта обязательны на всём протяжении разработки — не откладывать на полировку.

### 1. SQLite WAL mode
В `db/base.py` при инициализации БД обязательно выполнить:

```python
PRAGMA journal_mode=WAL;
```

Нужно, чтобы параллельная запись результатов матчей и чтение статистики не лочили SQLite под async-нагрузкой.

**Где фиксируется:** этап 1 (критерий готовности) + проверка на релизе (этап 8).

### 2. FSM только в личных сообщениях
Ввод никнейма, счёта, бомбардиров и скриншотов — **только в ЛС с ботом**.  
Если команда/`callback` пришли из группы/супергруппы:

- не принимать ввод в чат;
- ответить коротко: продолжить нужно в личке;
- при возможности дать deep-link / кнопку перехода в ЛС (`t.me/<bot_username>?start=...`).

Чат не должен превращаться в свалку скринов и FSM-сообщений.

**Где фиксируется:** этапы 3 и 5 (регистрация, `/result_tova`, скрины).

### 3. Безопасная модерация
Вызовы Telegram API для `/warn`, `/mute`, `/ban` (и смежных: unmute/unban/kick) оборачивать в `try/except`.  
Если бота забыли сделать админом чата или не хватает прав — не падать, а ответить админу понятным сообщением об ошибке прав.

**Где фиксируется:** этап 7.

### 4. Ссылки на темы из `.env`
ID чатов и тем не хардкодить. Три чата ТЗ (`MAIN` / `RI` / `VSA`) + `TOPIC_*`. Пустой topic — не битая ссылка.

## Правила разделения модулей

1. **Хендлеры тонкие** — принимают апдейт, вызывают service, отвечают пользователю.
2. **Services без aiogram** где возможно — чистая логика БД/статы/картинок (проще тестировать).
3. **Клавиатуры и тексты** — не смешивать с бизнес-логикой.
4. **URL** — только в `keyboards/urls.py`.
5. **Один роутер на раздел** — меню / tova / matchmaking / results / admin подключаются в `bot.py` отдельно.
6. Не начинать следующий этап, пока не выполнен критерий готовности текущего.
7. **WAL** включается один раз в `db/base.py` и не отключается в хендлерах.
8. **FSM-ввод** (ник, голы, скрины) — фильтр `F.chat.type == "private"`; групповые апдейты только редиректят в ЛС.
9. **Модерация** — ни один API-вызов restrict/ban не должен уронить бота из-за прав.

## Рекомендуемый порядок работы в одной сессии

```
Этап 0 → 1 → 2          # быстро даёт «живого» бота по ТЗ-навигации
       → 3 → 4 → 5      # ядро TOVA
       → 6              # визуал и стата
       → 7 → 8          # модерация и релиз
```

Этапы **2** и **3** можно частично параллелить после этапа 1 (меню не зависит от никнеймов), но **4–6** строго последовательны.
